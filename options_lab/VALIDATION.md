# WTI Options Desk: validation and evidence boundary

Engine 0.2.0 · recorded 2026-09-23 · synthetic engineering fixtures only.

This companion application implements a reviewable workflow: identified market
inputs → editable volatility → model values and Greeks → indicative quotes →
integer proxy hedges → residual scenario risk. It does not route orders.

The benchmark changes futures prices, normal/lognormal volatilities and
timestamps. It measures deserialization, calibration, volatility diagnostics,
atomic calculation, full scenario repricing, integer optimization, JSON export
and independent output checks. Synthetic input generation and browser/network
paint are excluded. It is not a replay of observed market traffic.

## Regression coverage added after independent review

- Bad-book and bad-receive-time flags suppress affected calibration/quotes; normal
  structural flags remain accepted. Empty books cannot revive cached prices.
- Complete final-portfolio constraints include non-tradeable held instruments.
  An unrepairable position breach returns an explicit infeasible result.
- Quote sizing can identify a complete risk-reducing clip that restores the
  position limit. Partial fills are not described as a compliant repair.
- Failed replay records are consumed once, clear prior proposals and allow later
  valid observations to recover. Calibration exceptions also clear old results.
- Feed state is strictly boolean. Negative option premiums are rejected while
  zero option premiums and negative futures remain supported.
- Absolute CSO normal-volatility shocks cover a rise from zero; vanilla volatility
  can remain unchanged to expose basis risk.
- Session restoration checks hashes and semantic relationships, recalculates
  results, and is tested in a fresh Python process. Invalid imports do not replace
  the current session. Solver/environment differences can cause explicit refusal.
- Historical desk evaluation uses the UI's actual optimizer and rejects late
  information, missing exits, expiry crossings and silently dropped failed days.
- Acceptance gates independently check complete quotes, permitted instruments,
  costs, net stress risk and input versions rather than trusting solver labels.

## Reproduce

From the repository root, in the isolated options environment:

```bash
.venv-options/bin/python -m pytest tests_options -q
.venv-options/bin/python -m options_lab.validate --updates 1000
```

The [optional CI template](ci/options-desk.yml.example) runs the full options suite
and the original-research preservation gate on Linux once enabled. Copy it to
`.github/workflows/options-desk.yml` using credentials that can manage workflows.
The publishing credential could not add a workflow, so **this template is not
active and no options-specific cloud CI pass is claimed**. The recorded options
suite results above are local. Existing research CI continues to cover the
original inventory project.
The checked-in [preservation manifest](examples/research_baseline.json) contains
only paths and SHA-256 hashes of already-public research files. A local pre-change
manifest takes precedence when available. Missing baselines fail acceptance
instead of silently disabling the check.

Detailed logs, versioned results, local data and timing samples generated by the
commands go to `options_lab_runs/`, which is intentionally excluded from Git.
The original research release and GitHub Pages report remain separate.
